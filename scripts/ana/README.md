# 穴馬発掘ツール群（南関・競馬ブック地方）

人気薄の好走を"純粋に見抜く"ための解析ツール。展開・馬場の読みに、
追い切り気配／上昇物語／道悪適性／隊列ペース／サイン検証を重ねて穴を二重・三重に確認する。

## セットアップ（重要）
- 競馬ブック地方の閲覧 cookie を `scripts/ana/kb.conf` に置く（curl の `-K` 設定ファイル形式）。
  **kb.conf は cookie を含むため gitignore 済み・絶対にコミットしない。**
- 実行すると同ディレクトリに `arc/`（HTMLキャッシュ）が作られる（gitignore 済み）。
- 依存: Python 標準ライブラリ + `curl`（外部pkg不要）。

## レースID
`{開催ヘッド10桁}{R 2桁}{MMDD}` 例: 2026-07-17 浦和7R = `2026071305070717`
（浦和ヘッド: 7/13=2026071301 … 7/17=2026071305）

## ツール
| ファイル | 役割 | 実行例 |
|---|---|---|
| `monogatari.py` | コア: 談話取得・近走ID・物語文法スコア | `python3 monogatari.py 7 2026071305 0717` |
| `kehai_score.py` | ①気配(追い切り)スコア＝談話の追い切り語＋掲載馬の時計＋ブリンカー新装着 | `python3 kehai_score.py <rid>` |
| `ana_story.py` | ②上昇物語エンジン×人気薄フィルタ | `python3 ana_story.py <rid>` |
| `aptitude.py` | ③道悪実績・距離適性（種牡馬は参考） | `python3 aptitude.py <rid>` |
| `taretsu.py` | ④相対テン速度で隊列・ペース予想（丸数字通過対応） | `python3 taretsu.py <rid>` |
| `cyokyo_ana.py` | 調教ページ解析（掲載1頭の時計・脚色・矢印） | `python3 cyokyo_ana.py <rid>` |
| `ana_signals.py` | ⑤穴サイン命中率DB。記録→集計 | `python3 ana_signals.py <rid...>` / `python3 ana_signals.py sum` |

## 穴サインの現状（signals_db.json に累積）
`ana_signals.py sum` で、道悪巧者／小型×人気薄／上昇物語／気配好転／厩舎2頭出し人気薄
の各サインの3着内命中率が出る。**開催を重ねるほど"効くサイン"が確定する**のが狙い。
※ 2026-07-17（浦和1日6R）時点はサンプル僅少で参考値。

## 設計メモ
- 南関は調教時計が1レース1頭しか非公表のため、追い切り気配は主に厩舎談話の言葉で全頭に出る。
- 通過順は丸数字①..⑳が混じる → `taretsu._uncircle` で正規化（逃げ馬の後方誤判定を防止）。
- 結果ページは19/21セルとレイアウトが揺れる → 馬名・体重列を動的検出。

## ライブ通過キャプチャ（capture.py）── 実通過データの蓄積
競馬ブックの結果ページの通過順は**開催直後だけ生値**、時間が経つと`****`にマスクされる
（大井など。浦和も翌日以降マスク）。過去アーカイブでは脚質が取れない → **当日にキャプチャ**して
結果事実(通過・上がり・着順・人気・体重)を `tsuka_data.jsonl` に蓄積する。生HTML/cookieは保存しない。

- 開催当日に実行（例：月曜からの大井 回11、場コード10）:
  `python3 capture.py meet 2026 11 10 0720 0721 0722 0723 0724`
  （年 回 場 各開催日のMMDD…。日次はMMDDの並び順に1,2,3…が対応）
- 個別: `python3 capture.py rids <rid> ...` / 蓄積状況: `python3 capture.py stat`
- **maskedと出たら取得が遅い**＝その日のうちに取り直す。
- 蓄積後は実通過で脚質を復元でき、差し天国×実脚質での穴信号バックテストが可能になる。
- 種データ: 浦和 7/13〜17 全60レース（実通過）を収録済み。

### 現状の検証結論（大井・重要）
- 大井=差し天国（勝ち馬92%が上がり3位内）。ただしアーカイブ(通過マスク+上がり代理)では
  事前の穴信号は全てベースライン級（末脚力1.03x/前受けフェード否定/絶対上がり0.79x/ペース源なし）。
- **正解は「当日ライブで実通過を取り、浦和式の展開予想を適用」**。capture.pyで実データを貯めれば
  代理でない本物のバックテストに移行できる。
